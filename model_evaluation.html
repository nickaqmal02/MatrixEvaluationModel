Introduction

The question this report answers: why did Sentiri choose XLM-RoBERTa for sentiment analysis and BERTopic for topic modeling, instead of the alternatives?

The defense is not authority (“XLM-R is popular”) — it is evidence: define the requirements, compare candidates against them on the same data, and let the results justify the choice.

Requirements that drive model choice

# Requirement Consequence for model choice
R1 Malaysian chat text: Malay-English code-switching (rojak) Model must be multilingual at the token level, not translated
R2 3 classes: negative / neutral / positive, imbalanced Need macro-F1 + per-class recall, not accuracy alone
R3 Clinical context: distressed messages must not be missed Negative-class recall is the priority metric
R4 Deployment on a budget (Render + HF Inference) Model size + inference time matter
R5 Short, informal, noisy messages (WhatsApp-style) Model must handle 3–20 token messages without dilution

Candidates

Model Role in comparison Params
XLM-RoBERTa-base Generalist multilingual heavyweight (our pick) 278M
mBERT-base The older multilingual baseline 178M
IndoBERT-base-p1 Regional specialist (Indonesian/Malay) 124M
DistilBERT-multilingual Efficiency baseline 135M

Hypothesis: XLM-R wins on mixed rojak messages; IndoBERT may win on pure formal Malay. The per-message breakdown is the interesting finding — which is exactly what the evaluation is for.

Data

Source: 2,171 labeled WhatsApp messages (pos/neg/neutral) from the autism therapy domain. Same split (seed=42) for every model — a comparison is only fair if all candidates see identical train/test folds.

The cleaning pipeline (what the model actually sees)

The production pipeline cleans every message through MalayTextCleaner before it reaches any model. Two different cleaning profiles exist, because the two downstream tasks need different text:

Profile What it keeps Why
clean_for_sentiment negation words (tak, x, bukan), sentiment-bearing tokens Negation flips sentiment — removing tak turns “tak nak” into “nak”
clean_for_topic_modeling domain words, stems Topic modeling needs dense topical signal; stopwords are noise

Shared layers in _base_clean (both profiles inherit): normalizer → typo/slang mapping → emoji conversion → PII removal (person names + honorifics, before steming) → curse filtering.

The cleaner is rules + data. The code is ~450 lines; the knowledge lives in 12 curated data files under chat_analyzer/data/. This is deliberate: domain experts (admin) can improve the pipeline by editing data, not code.

Part 1 — Why not a lexicon approach?

The initial direction (suggested by our lecturer) was a lexicon-based sentiment analyzer: score each message by looking up its words in a sentiment dictionary. We investigated and rejected this approach — for three evidence-backed reasons.

1.1 The resource gap (weaker argument)

Malay has no maintained, ready-to-use sentiment lexicon — nothing comparable to English’s VADER, SentiWordNet, or AFINN that one can download and run today. What exists are induction methods in research papers (Omar et al. 2017 maps WordNet Bahasa onto English SentiWordNet; cross-lingual synset-mapping experiments exist), whose outputs are not published as reusable artifacts. This is a real but recoverable obstacle — one could build a domain lexicon — so it alone does not justify abandoning the approach. The decisive arguments follow.

1.2 Contextual polarity flips — the measured failure mode

A lexicon assigns each word a prior polarity (dictionary meaning). But words carry their contextual polarity from the sentence. In therapy-progress chats, this gap is not an edge case — we measured it:
